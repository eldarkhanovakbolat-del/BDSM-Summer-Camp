# 架构与数据流

## 目标

公开版只规定夏令营需要什么能力，不规定用户必须使用哪一家模型、网关、记忆库或部署平台。私人系统通过 Provider 接入，不进入仓库。

## 组件

```text
┌──────────────── 浏览器 ────────────────┐
│ React 页面                            │
│ 目录 / 入营设置 / 会话 / 知识卡 / 观众 │
└──────────────────┬────────────────────┘
                   │ 同域 /api
┌──────────────────▼────────────────────┐
│ 前端服务端转发                         │
│ 只转发请求，不保存或暴露模型密钥        │
└──────────────────┬────────────────────┘
                   │ 内网 CAMP_SERVER_URL
┌──────────────────▼────────────────────┐
│ 夏令营 Python 服务端                   │
│ 会话编排 / 提示上下文 / 限流 / 来源获取 │
├─────────────┬──────────────┬───────────┤
│ SQLite      │ AI Provider       │ Memory   │
│ 会话与缓存   │ 主 AI / 可选观众端点 │ Provider │
└─────────────┴──────┬────────────┴────┬─────┘
                     │                 │
              用户的模型后端       用户的记忆系统
```

### 前端

`app/ExperienceApp.tsx` 提供三层体验：

1. 选课目录：从本地目录立即渲染 BDSM 101、Theory、Disciplines，并支持搜索；
2. 入营设置：选择共学/体验、AI 显示名称、观众开关、语气和活跃度；
3. 会话房间：持续对话、知识卡、观众席、五种参与方式、返回目录。

浏览器用本地生成的随机 `visitor_id` 查找自己的会话。这只是单人自托管的便利标识，不是账号认证。

### 同域 API 转发

`app/api/[...path]/route.ts` 把浏览器的 `/api/*` 请求转给服务端的 `CAMP_SERVER_URL`。因此：

- 浏览器看不到 AI 或记忆系统密钥；
- 前端和 API 可以使用同一个域名；
- 私人服务端无需直接暴露在公网。

只有明确需要浏览器直连独立 API 时才填写 `NEXT_PUBLIC_CAMP_API_BASE`，并同时正确设置 CORS。

### 夏令营服务端

`server/app.py` 只使用 Python 标准库，负责：

- 提供目录、会话和消息接口；
- 在 SQLite 中保存会话与消息；
- 按词条从 BDSM Wiki 获取原文，并在 SQLite 缓存；
- 组合主 AI 本轮所需的最小上下文；
- 调用 AI Provider；
- 可选地召回与写入长期记忆；
- 使用独立请求生成文字 AI 观众。

### Provider 边界

- `server/providers/ai.py`：唯一负责调用模型后端的地方；
- `server/providers/memory.py`：唯一负责调用长期记忆系统的地方。

接入特殊后端时，优先增加一个 Provider 类，保持会话、词条和界面代码不变。

## 一轮主对话怎样发生

```text
用户选择“说话 / 行动 / 想法 / 提问 / OOC”并输入文字
  → 服务端确认 visitor_id、session_id 与输入长度
  → 读取当前会话的主 AI 历史
  → 如启用，按 visitor + main 命名空间召回长期记忆
  → 读取当前 BDSM Wiki 原词条缓存
  → 组合：可选原有人设 + 可选记忆 + 最小模式引导 + 原词条 + 会话
  → AI Provider 生成主 AI 回复
  → 保存用户输入与主 AI 回复
  → 如启用，将本轮主对话写入长期记忆
```

共学模式的最小引导要求 AI 以教学为外壳与用户共同探索，并维持原有人设、关系、浪漫氛围与性张力。体验模式的最小引导要求 AI 与用户沉浸于围绕词条展开的纯文字情境。应用不会额外加入削弱成人体验的冷却提示。

## 观众隔离

主回复完成后，如果用户开启观众：

```text
当前一轮用户文字 + 当前一轮主 AI 回复
  → 独立 audience 调用
  → 解析文字评论、英文动作和回复灵感
  → 保存为明确标注的 AI 观众消息
```

观众请求不包含：

- `AI_PERSONA_FILE`；
- Memory Provider 的召回结果；
- 主 AI 的长期关系身份；
- 完整历史会话；
- BDSM Wiki 正文。

观众调用使用 `X-Camp-Purpose: audience` 和独立的 session 标识。自定义网关应利用这个标识选择无私人记忆的身份；无法隔离的用户可通过 `AUDIENCE_AI_*` 环境变量使用独立模型端点。观众失败不会让主回复丢失。

## 数据在哪里

默认 `data/camp.db` 包含：

- 会话设置；
- 用户、主 AI 与观众消息；
- 回复灵感；
- BDSM Wiki 词条缓存。

`.gitignore` 会排除数据库、`.env`、日志、人设文件和常见缓存。备份时应将数据库与服务端秘密分开保存。

## 当前信任模型

首版面向单人自托管或彼此完全信任的环境：

- `visitor_id` 存在浏览器 localStorage，可被持有数据库访问权的人绕过；
- 没有账号、密码、权限或租户隔离；
- 进程内限流只用于减少误操作，不是互联网级防滥用方案。

如果公开给不互相信任的多人使用，必须先增加真正的身份认证、数据库所有权校验、持久限流、审计与独立记忆命名空间。

## 有意不做的事情

- 不绑定特定模型或网关；
- 不公开任何私人后端实现；
- 不在浏览器保存模型密钥；
- 不把完整第三方文章打包进仓库；
- 不在首版加入通用 MCP；
- 不在首版加入多人账号、支付或插件市场；
- 不让文字观众读取主 AI 私人记忆。
